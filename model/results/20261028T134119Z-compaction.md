# Compaction model: log cut and row snapshot

Model: model/tla/Compaction.tla, commit of this file.
Tool: TLC 2.19, breadth-first search, 1 worker, option -deadlock
(the model stops at MaxIdx, and that end is not a fault).
Machine: session VM, 4 processors, Linux 6.18.

## What the model holds

- A decided log of operations put(k, v) and delete(k). A majority
  holds each decided entry.
- Each node applies its log in order. A row keeps the index of its last
  change. A delete leaves a deletion mark with its index.
- A node cuts its log at any index it has applied (mode 1, owner
  2026-10-28).
- A node fetches log entries from a node that still holds them.
- Delta snapshot: a node behind receives only the rows and marks with
  an index above its own applied index.
- Full snapshot: a node behind receives all rows.
- A node drops the deletion marks up to an index h. The horizon of the
  node becomes h.

## Invariants

- StateMatchesLog: the live rows of each node equal the fold of the
  decided log up to its applied index.
- DecidedAtMajority, TypeOK.
- CanCatchUp: a node behind always has a way to catch up.

## Bounds

Nodes {n1, n2, n3}, Keys {k1, k2}, Vals {v1}, MaxIdx 3, symmetry over
nodes and keys. MaxIdx 4 did not end within 15 min.

## What the results show

- Without deletion marks, a delta snapshot misses a delete. The node
  behind keeps the deleted row.
- When marks are dropped only after all nodes passed their index, the
  horizon check is never false: it gives the same state space.
- Marks can be dropped after a majority passed, if a node behind the
  horizon of the sender gets a full snapshot instead of a delta.
  Without that check, the delete is lost.

## Decision

The owner chose on 2026-10-28: marks are dropped after a majority
passed their index, and a node behind the horizon of the sender gets
the whole state. MC_compaction checks this form. MC_compaction_all_marks
keeps the other form for comparison.
