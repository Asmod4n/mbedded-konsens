# ClusterStop: the clean stop in a repair and the stop of the whole cluster

Plan: doc/plan-cluster-stop.md section 3. Model: model/tla/ClusterStop.tla at
the commit of this file. Configs: model/tla/MC_cluster_stop_*.cfg.

Bounds of every run: three nodes, MaxBallot 2, MaxLog 1, MaxCrash 1,
MaxDamage 1, MaxStop 1, AutoRepairs 1. The clean stop of an operator is
bounded to a node in a repair; with the clean stop of a running node in
the model, BFS did not end within five minutes at MaxBallot 3 or MaxLog 2.

Tool: tla2tools.jar from the GitHub release v1.8.0 of tlaplus (TLC2
2026.11.06.222357, rev d8fb231, sha256
e1f11b75c4b5bc4478ba0ac5cb6ae28e40a01b0016bc33e0aa97da22dfdbcd7f), Java 21,
3 workers on 4 cores, Intel Xeon 2.10 GHz, Linux 6.18.44, user root. Builds
of the library ran beside the simulation for part of its time.

The trace of MarkBelowDamage: node 1 leads ballot 1, node 3 acknowledges,
the entry is chosen. Node 1 finds a damage at index 1, stops cleanly with a
mark whose verified index is 0, starts clean, repairs from node 3 and votes.
Node 2 leads ballot 2 with the promises of nodes 1 and 2, which report no
entry, and the chosen entry is lost. This is wrong assumption 17 of
doc/plan-clean-stop.md.

The BFS without a mutation did not end. Every state up to depth 23 is
explored, and every trace of the mutations is shorter than that.
