Conclusions that set the later bounds:

- Without a limit on loss, duplicate and timeout, and with all faults in one run, the state space grows by a factor of about 3 to 6 per level. The interesting traces are 14 or more steps long. The bounds of plan section 6 cannot be checked exhaustively within 2 h at about 1 million distinct states per minute.
- The later runs therefore limit the number of calls of handle_leader (2), the number of losses, duplicates and timeouts (1 each), and take one fault class per run.

Modelling error found in run a1, first: in `ResendMessageTimeout` the conjunct `chan' # chan \/ phase' # phase` stood before the conjuncts that set `chan'`. TLC cannot evaluate a primed variable before it is set. The conjunct now stands after them. It makes a timeout that sends nothing and changes nothing a disabled step, so it does not use up the timeout bound.

Changes of the model during these runs: the network action `reconnected` (mod.rs:343-357, called by the network layer) was removed; `reconnected` stays where the source calls it itself (follower.rs:223 and follower.rs:234). A VIEW was added that drops values no action reads in the current role and phase (leader_state of a Follower except n_leader, the cached Promise outside (Follower, Prepare), current_seq_num outside (Follower, Accept)).
