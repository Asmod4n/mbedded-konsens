# What: the cost of three forms of the read-back of plan
# doc/plan-lmdb-only-source.md section 2.4 item 1, for each message of a
# step. A message reads promise, accepted round, decided index, the last
# log key and the count of entries, appends one entry with MDB_APPEND
# and writes the decided index. A step is the given number of messages
# in one write transaction and ends in a durable commit. Each sample is
# 10 steps; the line gives the median of 31 samples in ns per message.
# Arms (after the commit of each step):
#    1: no read-back.
#    8: a read transaction gets each entry of the step and the decided
#       value; their pages leave the cache (madvise MADV_PAGEOUT, then
#       posix_fadvise DONTNEED, then mincore counts what stayed); a new
#       read transaction gets and reads them again.
#   13: as 8, and the two LMDB meta pages also leave the cache.
#   14: as 8, but the whole used part of the file leaves the cache, so
#       the new read transaction also reads the branch pages from disk.
# Why: review 1 of the plan, finding 6: the read-back must also cover
# the LMDB meta pages and the pages on the path. Branch lmdb-only-source.
