What was measured
- konsensd writes of 64 B through PUT /kv, three nodes, one btrfs file system per node (loop images, compress=zstd:1), 1 and 64 in flight.
- Arms, each its own binary, g++ 16.2.0 Release (build-konsensd.sh):
  konsensd_g16F2: commit dd179cb (sha256 486d1b0efe993860); konsensd_g16F2cp: the same binary copied (A/A).
  konsensd_g16D1: commit 6207a7d, F2 plus the meta record kept in memory per write transaction (sha256 51f8368f11e53270).
- 3 rounds; in each round the arms alternate; each cell is the median of 3 samples (300 writes at 1 in flight, 8192 at 64). Raw SQLite on the file system of node 1 in each round.
- podman --cpus=3, user 1001, not pinned, kernel 6.18.44-fc-v185, Intel Xeon (Firecracker VM), libsqlite3-0 3.53.4-2. Scripts arms.sh and cluster.sh outside the tree: 7d685173ed1f99df d9bad1b2fb550242.
- CPU per write: user and system time of the three nodes. The name konsensd_g16F2cp is longer than the 15 bytes of a process name, so pgrep found no process and its CPU columns read 0. Its rates are valid.
