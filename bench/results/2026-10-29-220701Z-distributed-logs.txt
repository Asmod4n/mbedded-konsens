# One write benchmark for konsensd, other replicated logs and raw SQLite
Plan: doc/plan-bench-distributed-logs.md (this branch). Three nodes per system in one podman container (--cpus=3 of 4 processors), user bench (uid 1001), nice 0, not pinned. Data on btrfs zstd:1 on a loop file (fs line below).
Operation: one write of a new key with a random value of 64 B or 1 KiB to the leader, closed loop, 1 or 64 writes in flight. 15 samples per run after 2 warm-up samples; 50 writes per sample at 1 in flight, 256 at 64. 3 rounds; the systems run one after the other in each round, each from fresh data directories.
konsensd: main f65926a (code as main a6e8b50), Release, g++ 16 twice (g16, g16aa: the noise floor; both binaries have the same SHA-256) and clang 22. A PUT probe must answer before the first sample.
raw_sqlite: one process, WAL, synchronous=FULL, PASSIVE checkpoint at 1000 frames; batch 1 = one commit per write (row c1), batch 64 = 64 writes per commit (row c64). 31 samples of 200 writes.
Not done from plan 4.7: fsyncs per write (strace -c) and CPU time per write. Not done from plan 2.1: Omni-Paxos.
A row with fail>0 had a driver run end on a request that got no answer in 30 s (driver_failed in the raw output).
