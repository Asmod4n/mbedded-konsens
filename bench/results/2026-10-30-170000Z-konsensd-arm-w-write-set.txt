konsensd: arm W (the base of Execute-Verify as a write set in memory) against 1011ddc, six rounds

What was measured
- konsensd writes of 64 B through PUT /kv, three nodes, Unix sockets, sync_by_the_caller = true.
- Arms, each its own binary, g++ 16.2.0 Release: konsensd_g16HS2u (1011ddc), konsensd_g16WS2u (1011ddc plus a patch outside the tree, sha256 f9a03ef7f55ebd70), konsensd_g16HS2uc (the H binary copied, A/A).
- The patch: begin_the_nested_transaction returns a write set in memory instead of a SAVEPOINT. The write set holds a map of keys and a map of sessions; an erased key or session is held as an empty value. A read looks in the maps first and then in the open transaction. The base is built again for each step, as before; only the place of its writes changes. Nothing else changes.
- Tests of the changed paths, all green with the patch: test_execute_verify (31 cases), test_node (12), test_sync_by_the_caller (12), test_simulation (2, 1 skipped), test_group_commit (13), test_simulation_clients (1).
- 6 rounds; in each round the arms alternate; each cell is the median of 3 samples (300 writes at 1 in flight, 8192 at 64). Raw SQLite alone on the file system of node 1, and three at once on the three file systems, in each round.
- podman --cpus=3, user 1001, not pinned, seccomp profile with io_uring, kernel 6.18.44-fc-v185, three btrfs loop images compress=zstd:1 on one host disk, libsqlite3 3.53.4.
- Binaries: konsensd_g16HS2u e4a23155a4362697; konsensd_g16WS2u ebdc299e0511be26; konsensd_g16HS2uc e4a23155a4362697. Script outside the tree: arms.sh 12cf275a0325f51c.
- A first run of the same arms gave no number: a restart of the machine had unmounted the loop images, and every start failed.

- A/A floor: 0.3 % at 1 in flight, 6.3 % at 64 in flight.
- W against H: +7.4 % at 1 in flight, +7.8 % at 64. W against the H copy: +7.1 % at 1, +1.5 % at 64.
- At 1 in flight W is above the floor; W is first or level in each of the 6 rounds. At 64 in flight the difference is under the floor and is not a difference.
- Raw SQLite three at once, median of each round's three processes: 785 to 800 writes/s at 1 write per commit, 44 418 to 51 046 at 64. W at 1 in flight is about 62 % of it.
