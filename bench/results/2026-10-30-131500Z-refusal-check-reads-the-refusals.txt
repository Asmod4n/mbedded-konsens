What was measured
- The rate of one cluster over nine samples in a row, as in 2026-10-30-123000Z-write-path-slows-with-each-sample.txt: 4096 writes of 64 bytes per sample, 64 in flight, no restart between samples. Same bed, container, seccomp profile and compiler.
- Arms, each its own binary, g++ 16.2.0 Release (build-konsensd.sh), option sync_by_the_caller off in both: konsensd_g16S2 (3fa6039, fa81e1156f810499) and konsensd_g16R1 (2a8cd3b, b44668830471453d). Order S2 R1 S2 R1. spread.sh 3716129a03e6b8af.

Cause found before this run
- callgrind on all three nodes on tmpfs (vg3.sh): on the node that was leader at the end, selection::find_the_entries_that_a_majority_refused took 2 266 instructions per write in sample 1 and 738 854 in sample 9. It walked each done record that the leader appended in its ballot, in each step. That set has no bound.
- 2a8cd3b walks the refusals instead. The result is the same list.
- The same run on tmpfs showed the drop as on the disk (9 544 to 1 491 writes/s for S2), so the disk was not the cause.
