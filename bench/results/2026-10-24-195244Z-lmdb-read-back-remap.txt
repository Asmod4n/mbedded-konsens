# What: the cost of the read-back from the disk with the page checksums
# of LMDB 1.0 and MDB_REMAP_CHUNKS. Each message of a step reads
# promise, accepted round, decided index, the last log key and the
# count of entries, appends one entry with MDB_APPEND and writes the
# decided index. A step is the given number of messages in one write
# transaction and ends in a durable commit. Each sample is 10 steps;
# the line gives the median of 31 samples in ns per message.
# Arms:
#    1: the step, no checksum, one map of the file.
#    8: as 1, then a read transaction gets each entry of the step and the
#       decided value, drops their pages (MADV_PAGEOUT on the value
#       range, then POSIX_FADV_DONTNEED on the same file range), checks
#       with mincore and reads the bytes again from the disk.
#   16: the step with mdb_env_set_checksum (CRC32C through the SSE 4.2
#       instruction, 4 bytes per page) and MDB_REMAP_CHUNKS, then a read
#       transaction reads each entry of the step and the decided value
#       again (from the cache).
#   17: as 16, but the read transaction drops the pages of the values
#       (MADV_PAGEOUT on the value range in the chunk mapping), then
#       POSIX_FADV_DONTNEED on the whole file, because a value address
#       in a chunk mapping does not give its file offset; mincore checks;
#       the transaction ends; a second read transaction gets the values
#       again, so LMDB checks the checksum of each page that it reads
#       from the disk.
# resident_after_pageout counts the pages of the values that mincore
# still finds in memory after the drop. sum_calls counts the calls of
# the checksum function in one run.
# Why: the owner, 2026-10-24 19:45, chose the page checksums with
# MDB_REMAP_CHUNKS; plan doc/plan-lmdb-only-source.md 2.4 needs the
# read-back in this form. Branch lmdb-only-source.
# Facts read in mdb.c (deps/lmdb, LMDB 1.0.2): mdb_rpage_encsum
# (:6862-6886) checks a page only when its bit in muse is clear, and sets
# the bit. mdb_txn_end (:3773-3792) clears muse of a chunk when its last
# reference ends. So a page is checked once in each transaction, but not
# again while another live transaction holds the same chunk.
# How: one source file outside the tree (at the end of this file), one
# binary for each arm and an A/A copy (copy b) built the same way. 7
# rounds; the order of the arms and of the copies turns round each even
# round. Each binary runs in a fresh LMDB directory on ext4 (/dev/vda,
# virtio disk of the VM), deleted after the run. The code is not in the
# tree, so no commit holds it; the tree at the run: branch
# lmdb-only-source c052940, not used by the bench.
