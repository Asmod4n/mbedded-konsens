What was measured
- Arm S: konsensd with sync_by_the_caller = true syncs the WAL through io_uring (IORING_OP_FSYNC, IORING_FSYNC_DATASYNC) and computes the next steps while the sync runs.
- Arms, each its own binary, g++ 16.2.0 Release (build-konsensd.sh): konsensd_g16D1 (6207a7d, 51f8368f11e53270), option off; konsensd_g16S (7f152f1, a5df58a4b0bed494) and konsensd_g16Scp (the same binary copied, A/A), option on.
- io_uring of the kernel: podman with the default seccomp profile plus io_uring_setup, io_uring_enter and io_uring_register (ccce5e3325a9449a).
- konsensd writes of 64 B through PUT /kv, three nodes, one btrfs file system per node (loop images, compress=zstd:1), 1 and 64 in flight. 3 rounds; in each round the arms alternate; each cell is the median of 3 samples (300 writes at 1 in flight, 8192 at 64). Raw SQLite on the file system of node 1 in each round.
- podman --cpus=3, user 1001, not pinned, kernel 6.18.44-fc-v185, Intel Xeon (Firecracker VM), libsqlite3-0 3.53.4-2. Scripts arms.sh and cluster.sh outside the tree: f41eed0c3b72e356 d9bad1b2fb550242; arms.sh adds "sync_by_the_caller = true" to the node table of the arms that end in S or Scp.
