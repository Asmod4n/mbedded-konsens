# What: which calls take the pages of a file that the process maps out
# of the page cache. Not a speed measurement: each line is a count of
# resident pages that mincore reports.
# Why: plan doc/plan-lmdb-only-source.md section 2.4, the read-back
# after a commit must read from the disk.
# How: three small programs outside the tree (at the end of this file),
# g++ 13 -O1 (the compiler of the host), run on the host of the VM, ext4 on /dev/vda. Each writes a
# file of 64 pages, fdatasyncs it, maps it MAP_SHARED, touches each
# page, and then tries one way to drop pages. The tree at the run:
# branch lmdb-only-source fe79246, not used by the programs.
# kernel 6.18.44-fc-v153; g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0; mount /dev/vda ext4
#
# ---- t: whole file ----
after touch: 64/64
after fadvise only: 64/64
madvise PAGEOUT=0 
after pageout: 0/64
after pageout+fadvise: 0/64
fresh map of cache: 0/64
# ---- t2: one page, then 16 pages, after one pwrite of 64 pages ----
resident 64/64
one page out: page8=1 total=64
16 pages out: total=64
fadvise page8 after: page8=0
# ---- t3: one page (page 8); mode 1 fadvise; 2 MADV_PAGEOUT then fadvise; 3 MADV_DONTNEED then fadvise; 4 MADV_DONTNEED of the whole map then fadvise ----
mode 1: page8=1 total=64
mode 2: page8=0 total=63
mode 3: page8=1 total=64
mode 4: page8=1 total=64
